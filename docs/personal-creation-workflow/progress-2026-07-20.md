### Runner 稳定性与安全

- 插件通过系统 Node 后台启动 Runner；Obsidian 重载后任务不会因 Electron 子进程退出而中断。
- 插件保存稳定设备 ID；Vault 保存 owner、heartbeat 和 fencing epoch。
- 新设备只有在旧设备 relinquish 后才能接管，接管时 epoch 增加；旧 epoch 不能继续提交结果。
- Task 领取时写入 owner、epoch 和 lease；运行中刷新租约。
- 同设备同 epoch 的过期租约可恢复；外部设备或旧 epoch 的租约转为 `waiting_user / ownership_conflict`。
- 临时错误最多自动执行三次，退避为 30 秒、120 秒；Attempt 历史保留。
- 推广暂存结果前重新核验 owner 和取消状态；已取消输出不会进入正式 Artifact。
- 同步文件会清理邮箱、Vault/用户/临时目录以及疑似 secret 的值。
- 缺少 Skill、凭证/权限、输出格式错误、执行权冲突现在分别显示原因和恢复动作，不再统一误导为普通重试。
- Runner 回执保存本次 Attempt 实际使用的全部输入 SHA-256；被用户接受的 Skill 输出会形成稳定 Artifact ID、不可变 Artifact 版本 ID、内容哈希、依赖哈希与前序版本链接，Approval 明确指向接受的 Artifact 版本。
- 人工版本保存真实内容 SHA-256，并以独立用户版本记录；双平台下游失效状态按交付物隔离，小红书输入变化不会倒退微信交付物。
- 新增 Runner 专用的托管 Skill 清单与本机安装器。新任务固定来源、版本、内容摘要、清单摘要、依赖声明和权限范围，并写入 `project-lock.yaml`。
- 缺失或被篡改的 Skill 在 Attempt 创建前暂停；界面展示来源、固定版本、两个摘要、依赖与读/写/联网/凭证权限，用户确认后才安装到 Reading Capture 本机运行目录，不修改全局 Codex Skills。
- Skill 权限扩大时逐类展示新增项并要求重新批准；安装或升级摘要不匹配时保留旧 digest，不影响旧锁继续运行。
- Writing Styles 固定提交 `0e85e2f8…` 已真实安装到本机受控目录，并通过二次 SHA-256 校验；新版 Runner 已以显式 `--skill-runtime` 参数启动。
